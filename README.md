# sky-pm-demand-analyzer

> 产品经理需求分析与转换助手 —— 帮你判断需求真伪、拆解MVP、转换为标准产品需求、多需求优先级排序。

## ✨ 核心能力

| 模块 | 功能 |
|---|---|
| **🔍 需求分辨** | 三层挖需法、真伪判断清单、痛点强度评估、四象限决策矩阵、五类危险需求识别、MVP切割原则 + 内置6项质量自检 |
| **🔄 需求转换** | 需求重写公式、ROI三角评估、高回报需求判断、创造力三板斧、方案对比模板、PRD标准结构 + 内置6项质量自检 |
| **📊 优先级排序** | RICE打分法、MoSCoW分类法、价值/复杂度矩阵、排序输出模板 + 内置6项质量自检 |

> ✨ **v1.1.0新增：** 每个模块输出后自动跑一遍质量自检清单，缺漏自动补充，不用你自己盯。

---

## 🎯 适用场景

- 收到用户/老板/业务方提的需求，不知道该不该做
- 不知道怎么把口语化的需求转成标准PRD
- 多个需求堆在一起，不知道先做哪个
- 需要快速判断一个需求是真痛点还是伪需求
- B端、C端产品经理都能用

## 🚀 使用方式

### 触发方式
直接跟AI助手说需求相关的问题，比如：

| 你说的话 | 触发能力 |
|---|---|
| "帮我分析一下这个需求：用户说要加个导出Excel功能" | 需求分辨 + 转换 |
| "这个需求怎么做MVP？" | 需求分辨 + MVP方案 |
| "把这几个需求排个优先级：xxx、xxx、xxx" | 优先级排序 |
| "这个需求要不要做？" | 需求判断 |
| "帮我把这个用户需求转成产品需求文档" | 需求转换 |

### 输出形式
每次分析都会输出**表格化的需求分析卡片**，包含：

1. **需求判断卡片** —— 真伪/痛点/成本/象限/结论
2. **重写后的产品需求描述** —— 用标准产品语言重写
3. **方案对比** —— 保守方案 vs 创新方案
4. **待验证假设 & 风险** —— 关键假设和潜在风险

## ✅ 内置质量自检体系

每个模块输出后，模型自动跑一遍自检清单，缺漏自动补充：

| 模块 | 自检项数 | 检查什么 |
|---|---|---|
| 需求分辨 | 6项 | 有没有挖现状？痛点有没有三维度打分？有没有识别危险需求？有没有列待验证假设？ |
| 需求转换 | 6项 | 有没有用标准公式重写？有没有两个方案？成功指标可衡量吗？有没有说清楚边界？ |
| 优先级排序 | 6项 | 有没有量化打分？有没有考虑战略对齐？有没有说明排期理由？有没有识别依赖关系？ |

> 自检是自动的，用户不需要看到checklist，只需要看到最终成品——缺了什么模型自己补上。

## 📐 框架详解

### 需求分辨框架

- **三层挖需法**：表面诉求 → 行为动机 → 底层痛点
- **真伪判断清单**：8个是/否问题，量化判断需求真实性
- **痛点强度三维度**：频次 × 损失 × 覆盖范围（加权打分）
- **四象限决策矩阵**：痛点强度 × 实现成本，对应四种处理策略
- **五类危险需求识别**：解决方案式需求、个性化定制、老板拍脑袋、竞品跟风、临时一次性需求
- **MVP切割原则**：砍到能解决80%痛点的最小闭环

### 需求转换框架

- **需求重写公式**：场景 + 用户 + 痛点/目标 + 成功指标
- **ROI三角评估**：用户价值 × 商业价值 ÷ 实现成本
- **高回报需求特征**：6条判断标准
- **创造力三板斧**：重新定义问题、跨界迁移、主动预判下一步
- **方案对比模板**：保守方案 vs 创新方案的6维度对比
- **PRD标准结构**：7个模块的标准PRD模板

### 优先级排序框架

- **RICE打分法**：Reach × Impact × Confidence ÷ Effort
- **MoSCoW分类法**：Must / Should / Could / Won't
- **价值/复杂度矩阵**：四象限快速排序
- **排序输出模板**：标准化优先级表格

## 🧠 B端 vs C端差异

| 维度 | B端侧重 | C端侧重 |
|---|---|---|
| 痛点判断 | 看ROI（能不能帮客户赚钱/省钱） | 看体验爽不爽 |
| 覆盖范围 | 大客户需求权重高 | 普通用户数量权重高 |
| MVP标准 | 能跑通核心业务流程就行 | 要够好用，不然用户直接不用 |
| 成功指标 | 效率提升、成本降低、转化率 | 留存、时长、NPS |
