# 需求分析案例库

10个模拟案例：B端5个、C端5个。下文「已知」均指案例给定的模拟输入，不代表真实业务记录或助手已独立核验；「建议目标」「假设」不作为事实。数字不可照抄到实际分析。

案例用于说明判断方式，不替代框架。信息不足时保留未知；问题成立、原因成立、方案有效、投入合理分别判断，不按人数、提需来源或案例相似度直接定结论。

## B端案例

### 案例1：解决方案式需求

**原话：**「销售整理客户数据太费时间，加个导出Excel功能吧。」

**已知模拟输入：**任务观察显示，100名目标用户中的60名每周汇报一次，整理约2小时；已有导出能力，但格式不匹配。

**常见错误：**直接新增导出按钮，或把60%的覆盖和低成本都从原话中猜出来。

**分析与处理：**问题是整理交付数据的负担。按频次2、损失2、覆盖3，痛点为2.25，属中档；候选处理的成本未知，不能直接定位低成本并承诺立即做。先检查导出配置、现有模板和流程，只有需新增能力才进入转换。

**需求重写：**销售在每周汇报时需要把客户数据整理成符合汇报要求的内容，建议将单次整理从案例已测的2小时降至10分钟以内；该目标需确认并验证。输出范围、权限和交付格式需补充。

### 案例2：个性化定制需求

**原话：**「我们必须三级审批，你们单独给我们做一个。」

**已知模拟输入：**客户A使用三级顺序审批，产品当前固定两级。其他客户是否有相同变化未知。

**常见错误：**写死客户例外，或直接扩成全功能工作流平台。

**分析与处理：**客户A的流程缺口可核对，但多客户复用仍是假设。比较已有配置、受控局部扩展和有限配置能力；有新增能力需要时交接抽象。业务模型候选包括申请、审批节点、记录、审批人，关系、权限及撤回规则分别确认。

**需求重写：**企业管理员需要让申请按已确认的审批层级与人员流转。首期范围围绕A的三级场景和现有两级兼容性评估；不预设一级到五级、可视化编排或任意分支。配置效率与差错率基线、目标待确认。

**建设决策：**当前证据最多支持有限能力候选，不直接支持平台。若局部配置即可覆盖已知任务且解法明确，可直接交付；若配置机制能否适用仍有疑问，先做有限验证。不能只凭「三级比两级复杂」选择完整模块。

### 案例3：管理层提出展示大屏

**原话：**「做个数据大屏放墙上，看起来大气。」

**已知模拟输入：**只有该陈述，观看者、使用频次、决策或展示目标均未知。

**常见错误：**因来自老板就判伪，或把未知频次和覆盖都当成低分。

**分析与处理：**问题待验证。确认给谁看、用于决策还是商务展示、当前障碍是什么；管理层也可能是实际使用者。展示任务成立后可比较已有看板、现成工具和局部开发，不默认必须新建系统，也不默认展示没有价值。

**条件化重写：**若确认用于来访展示，则定义展示对象、内容与使用任务；相关验收和效果指标待确认，不能直接声称提高成交率。此时先补证据，不强行给PRD或双方案。

### 案例4：临时一次性需求

**原话：**「月底活动需要一个报名表单，开发一下。」

**已知模拟输入：**活动为一次性，需收集字段与截止时间已明确，现有报名工具是否满足权限和数据要求待检查。

**常见错误：**自动判低价值，或把一次性任务扩成通用表单平台。

**分析与处理：**任务可以真实且值得处理，优先比较现成工具、配置、服务与最小局部开发，说明成本、权限及交付要求。只有存在重复需求和复用收益时才评估通用能力，不因一次性就绝对禁止开发。

**交付描述：**在确认的数据边界内，于活动前完成报名收集和结果交付。字段、容量、截止时间及验收按实际要求确认，不凭空写「从1周缩短到1天」。

### 案例5：报表痛点与高投入方案

**原话：**「报表难用，做个自动报表系统。」

**已知模拟输入：**100家目标客户中80家每周整理报表，每家约10小时；完整BI平台初估60人天，纳入项待评估。

**常见错误：**直接建设完整BI，或不按量表就把痛点写高。

**分析与处理：**频次2、损失2、覆盖3，加权2.25为中档；同时说明目标群体合计约800小时/周的整理负担，不能仅凭档位忽视实际总量。先核对已有报表、配置和共性场景，比较固定报表、有限自动化与平台建设。问题真实不等于完整BI值得投入。

**MVP候选：**若样本确认少量固定报表能覆盖主要任务，可先交付固定生成与导出闭环；覆盖比例、报表数量和效果待验证，不把第二期拖拽、第三期大屏当成必然路线。

**需求重写：**运营人员需要减少每周整理报表的负担。成功指标按报表类型采集制作时长和修订量，再确认首期目标；若只有一个有效路径，可说明选择依据，不强造创新方案。

**建设边界反例：**只有少量固定报表有效的假设时，可用有限闭环验证；若核心流程、异常和持续价值都已验证，可直接规划业务模块并分期交付，无需重复验证问题；只有多个真实业务的稳定共性、净收益及维护责任成立后，才评估共用平台。三个条件分支不构成必经升级路线，验证失败应核对原因、调整或停止。

## C端案例

### 案例6：少数用户反馈夜间刺眼

**原话：**「晚上太亮，能不能出深色模式？」

**已知模拟输入：**100条评论中5条提及此问题，系统深色模式占比为3%；尚无夜间任务观察或受影响人群数据。

**常见错误：**用评论比例代替全体覆盖，或认为系统深色使用不足5%就证明问题是假的。

**分析与处理：**陈述支持这些用户表达夜间不适，但其发生条件、广度和方案效果待验证。系统主题偏好是线索，不等于需求真实性或影响范围。检查夜间场景、现有主题与亮度设置，比较主题、对比度或其他交互改善，低占比不构成否定依据。

**验证描述：**先观察目标用户的夜间任务及不适来源，提出并测试候选改善，效果口径与目标待确认。未证实的问题和方案保留未知，不直接承诺深色模式开发或判伪。

### 案例7：已有分享能力但入口难找

**原话：**「每次分享都要找半天，重做分享功能吧。」

**已知模拟输入：**15人任务观察中12人找不到入口；指出入口后均能完成，权限与功能可用。

**常见错误：**推断全体用户都受影响、自动判低成本立即做，或只安排培训。

**分析与处理：**样本中的发现困难已证实，完整重做分享能力的必要性未证实。先引导与检查入口、标签、上下文，提出局部改进。实际投入须估算，样本12/15不外推为全体80%。没有新增能力需要时在分辨路径结束，保留验收要求。

**验收建议：**选定目标任务和人群，在不提示入口时检查发现、完成情况及耗时，基线来源与目标分别注明，不凭空承诺分享率增长。

### 案例8：搜索失败不等于需要推荐

**原话：**「搜索太烂，每次找不到想要的内容。」

**已知模拟输入：**只有反馈，用户是在查找已知内容还是探索内容、内容是否存在、关键词和权限等未知。

**常见错误：**直接将原因写成用户不知道关键词，并把AI推荐定义为更优解。

**分析与处理：**用户表达查找受阻，具体任务和原因待核对。先观察查询、结果、索引与权限；明确查找和探索可有不同解法。可能是索引缺失、命名、排序、导航或内容缺口，不预设根因。无需为了创新而绕过明确查找任务。

**条件化重写：**在确认的查找场景下减少目标内容定位失败。只有实际存在不同有效路径才比较搜索、筛选、导航或推荐，基线、目标和验收按证据补充，不预设首屏推荐命中60%。

### 案例9：效率与防误操作冲突

**原话：**A希望简化步骤，B希望增加确认以减少误删。

**已知模拟输入：**两条反馈，熟练度、操作频次、误删原因、删除可恢复性未知。

**常见错误：**直接把A、B指定成新手和老手，再给模式开关作为标准答案。

**分析与处理：**分别核对任务和损失，可能涉及用户差异、风险场景差异或现有设计。对普通操作和不可逆操作分开判断，再比较默认值、局部确认、权限、撤销或配置。不能确认真实差异时先验证；开关不能绕过必要安全边界。

**交接描述：**在已确认操作场景中平衡效率与错误恢复，标出已知人群、风险与限制；可恢复性、误操作率、任务耗时及目标均待证据确认，不保证一种配置同时解决所有冲突。

### 案例10：多个需求排序与容量

**模拟输入：**本期目标提升核心任务完成率，剩余容量0.4人月。以下估算均已包含产品、设计、工程与测试，并假设所需角色本期可用、无额外前置依赖：

| 事项 | 已知依据 | 估计投入 |
|---|---|---|
| A 支付失败修复 | 已复现，正在阻断部分交易 | 0.1人月 |
| B 登录速度改善 | 有性能记录和任务影响，范围已确认 | 0.2人月 |
| C 会员体系 | 只有管理层想法，无任务与收益证据 | 未知 |
| D 深色模式 | 有少量反馈，原因和影响范围待验证 | 未知 |
| E 社交分享扩展 | 本期明确不做社交方向，也非必要维护 | 0.3人月 |

**常见错误：**只因老板提出会员就优先开发，替未知项编造RICE，或为凑满排期找小功能。

**分析与处理：**A先按必要事项安排最低修复范围，不因是否直接贡献增长而延后；B为Should、在剩余容量中安排；C、D单列待验证，不等同于伪需求、不承诺完整开发；E本期不安排，给重评条件。当前无完整Reach、Impact及效果证据，不生成RICE分数。

**实施建议：**A再B合计0.3人月，余0.1人月。可保留缓冲或另行估算小范围验证，不能将C、D免费塞入余量；没有依据承诺具体日历日期。若角色不可用、范围或前置变化，需要重新安排。

## 使用提示

先核对证据与范围，再参考相近案例。明确的修复、引导、配置和服务不必输出完整转换；进入转换或排序时，继续保留分辨阶段的未知项、约束和处理路径。
