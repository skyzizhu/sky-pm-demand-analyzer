## 1. 适用条件与信息继承

多个事项竞争资源时排序，事项可包括开发、修复、验证、配置或服务。复合反馈拆出的多个判断不自动变成多个独立需求。

继承分辨阶段的判断对象、证据来源、适用范围、未知项、紧急影响与约束，以及转换阶段的方案范围、复用与依赖。用户只要求排序且已有分析充分时，不重复完整挖需或生成方案；关键输入不足则标缺口，给条件化建议。

排序前明确决策目标、评估周期、Reach单位、投入范围；要安排本期范围时，还需容量、关键角色、已占用投入和已确认期限。没有容量时可以给相对优先级，不承诺日期或本期全部完成。

## 2. 方法选择

| 方法 | 使用条件 | 限制 |
|---|---|---|
| **RICE** | Reach、Impact、Confidence和Effort有可解释依据，且口径一致 | 序数和估计参与计算，不代表精确收益预测 |
| **MoSCoW** | 可判断必要性与本期范围，但量化依据不足 | 可同级，不强行制造精确排名 |
| **价值/复杂度** | 快速比较价值与投入，能说明依据 | 不替代必要事项、风险和依赖判断 |

可先MoSCoW分类，再对同类可比项用RICE。缺数据时选择分类、定性比较或待验证，不为表格完整编造分数。比较条件或区间不足以确定先后时，保留并列或说明何种信息会改变顺序。

## 3. 必要事项、战略与冲突

### 先识别必要事项

正在造成重大损失的故障、核心流程阻断、已确认的安全/数据正确性风险、硬性义务和已确认期限等，单独判断紧急性与不处理后果。先止损、确认最低处理范围，再安排长期治理；必要事项不必靠RICE高分证明优先级，也不因缺少对增长等阶段目标的直接贡献而被过滤。

不能只凭「可能流失」「大客户要求」或管理层催促就列Must，应说明证据、后果、期限及范围。边界或义务未知时标待确认，不自行认定。必要事项也受资源约束，不能默认全部承诺。

### 可选投入再看战略

| 对齐程度 | 处理方式 |
|---|---|
| 高度对齐 | 正常比较价值与投入 |
| 中度对齐 | 与主线机会成本比较，说明取舍 |
| 不符合本期重点 | 通常延后、缩小验证或使用外部方式，给重评条件 |
| 不符合产品定位 | 通常不投入当前方案，可重新定义或外部解决 |

战略取舍不改变已证实问题的真实性。目标不清时明确假设或待确认，不编造OKR。

### 检查需求冲突

检查相反诉求、受损人群和业务约束。可采用分层、场景规则、配置、分期等已评估方向，但不默认有两全解。必须取舍时说明受益、损失、补偿或限制，由PM决策；违反明确边界的方案不因高分通过。方案有实质变化时，重新核对影响、成本与依赖，不能沿用原分数。

## 4. RICE评分与证据

```
RICE得分 = (Reach × Impact × Confidence) ÷ Effort
```

| 维度 | 口径与依据 |
|---|---|
| **Reach** | 同一周期受影响的人数或付费客户数，选定一个单位；列来源与去重方式，不混用账号、席位、客户数 |
| **Impact** | 对所选目标的影响：3巨大、2高、1中、0.5低、0.25极小，说明假设和依据 |
| **Confidence** | 对上述预期覆盖与效果等估计的证据把握，按下表解释；不是需求来源或嗓门大小 |
| **Effort** | 产品、设计、工程、测试、迁移、上线及选定周期内维护的总投入人月，明确来源和换算；不能只计编码 |

### 信心来自证据

| 档位 | 使用依据 |
|---|---|
| **100%：证据较充分** | 在相近人群、条件和指标下有可复核的覆盖与效果验证，投入也有评估依据；该档位不表示结果必然兑现 |
| **80%：证据中等** | 有多项支持或小范围验证，但覆盖、效果迁移或部分投入仍为估计，指出剩余不确定性 |
| **50%：证据较弱** | 有可解释的间接依据，覆盖、效果与投入能作初步估计但尚无直接效果验证，标明关键假设 |
| **未知** | 只有功能请求，或关键估计无依据；不默认填50%，先补证据或定性分类 |

客户明确提出，可支持「该客户存在诉求」，不自动证明方案有效、会使用或产生收益。问题已证实但方案效果未知时，不能将问题真实性直接当成高信心。投入有显著不确定性时还要保留Effort区间，不能只靠Confidence掩盖。

### 可比性与未知项

Reach使用同一单位与周期，Impact针对同一目标，Effort统一人月换算及纳入范围。B端可采用付费客户数；客户经营影响可在Impact及必要性中有据说明，使用加权客户数须明确统一权重和来源，不临时给大客户加倍或重复计算收入影响。

Effort必须大于0；未知或零值时不计算。估算区间保留得分区间，不因微小分差就宣称确定先后。转换框架的效益投入得分不与RICE相加；只在同类且可比较事项中参考RICE。

以下均为模拟输入，仅演示计算。假设同一周期、同类事项、口径统一且不涉及必要事项与依赖：

| 需求 | Reach（人/季） | Impact | Confidence | Effort（人月） | RICE |
|---|---|---|---|---|---|
| A | 10000 | 2 | 80% | 2 | 8000 |
| B | 50000 | 1 | 100% | 5 | 10000 |
| C | 1000 | 3 | 50% | 1 | 1500 |

相对价值顺序B > A > C；未提供容量，不能据此承诺排期。实际使用需为这些输入补证据，不照抄示例分数。

## 5. MoSCoW与价值/复杂度

| 类别 | 判断依据 |
|---|---|
| **Must：必须处理** | 不处理会阻断核心任务、产生明确重大损失或无法满足已确认硬性要求，给证据与最低范围 |
| **Should：应该做** | 与目标相关且收益明确，但可分期或延后 |
| **Could：可选** | 增量改善，资源允许时考虑 |
| **Won’t：本次不做** | 明确本次不投入，说明原因与重评条件，不等于永久拒绝或伪需求 |

不强制各类比例。必要性判断优先于分数；同类内参考RICE、证据、期限和机会成本，不伪造精确度。

价值/复杂度矩阵可辅助比较：高价值低投入优先考虑，高价值高投入可拆分规划，低价值低投入仅在有余量且维护成本可接受时考虑，低价值高投入通常延后。矩阵不推翻必要事项、约束与依赖。没有quick win就明确说明，不要求人为新增小功能凑数。

## 6. 依赖、容量与实施顺序

### 先统一可交付范围

共用能力可作为前置支撑项配合场景增量，也可合并成可交付包评分，不同时给父项和子项重复计分。共享投入只计一次；覆盖去重，同一结果不重复累加。只做前置能力却无法交付用户结果时，要说明本期交付边界，不能算成完整收益。

### 再形成可行实施顺序

1. 先识别必要事项及其最低范围、期限和资源约束，避免将治理全量范围都标必须。
2. 标出前置依赖和外部条件。后置功能即使分高，也不能排在未完成的前置能力之前；必要时作为一组比较或分阶段交付。
3. 已知容量时，扣除已占用和必要事项投入，检查候选事项及前置成本能否容纳；不重复扣共享投入。
4. 同时检查关键角色、可用时间窗口和外部依赖。总人月够不代表可并行完成，不能由总投入直接推算日历日期。
5. 输出可承诺的最低范围、候选范围、剩余容量及未安排项。无容量或分工信息时只给条件化安排，不承诺日期。

必要事项已超容量时，明确缺口、止损与分期选项、延期后果和需PM决定的取舍；不强行塞满。没有能独立交付且符合目标的小项时，可保留余量用于验证、回归或风险缓冲，相关工作仍需计入容量，不能把剩余量当作免费投入。

## 7. 输出与自检

### 相对优先级表

| 价值优先级 | 事项 / 交付包 | 必要性与分类 | RICE或未知 | 证据与范围 | 前置依赖 | 理由与条件 |
|---|---|---|---|---|---|---|
| | | | | | | |

无量化依据时可用MoSCoW和定性理由，不必填RICE。未知与待验证事项单列，避免与已验证交付项混成确定排名。

### 实施建议（容量已知时）

| 实施顺序 | 本期范围 | 增量投入及角色 | 前置条件 / 期限 | 安排状态与原因 |
|---|---|---|---|---|
| | | | | |

表后列：总容量、已占用、必要事项及可选项投入、剩余量、未安排项、假设与关键风险。分别说明价值顺序与实施顺序。容量未知时改列需要确认的资源和依赖，不输出虚假的承诺排期。

## ✅ 优先级排序自检清单（三层评测）

### 第一层：完整性
- [ ] 是否继承证据、未知项和必要事项，未对所有事项强制打分？
- [ ] 是否将必要事项单独判断，再对可选投入检查战略与冲突？
- [ ] 是否识别依赖、去重覆盖与共享投入，说明可交付范围？
- [ ] 是否给出分类、理由与条件，区分价值顺序和实施顺序？

### 第二层：质量
- [ ] 数据有依据且周期、单位、目标和投入范围可比，Confidence未按来源赋值，区间未被掩盖？
- [ ] 客户业务影响及任何权重是否有依据，未重复计算？
- [ ] 是否只在存在有效低投入机会时识别quick win，没有则如实说明？

### 第三层：反面检查
- [ ] 是否因阶段战略或低分延误必要维护，或把缺证据的可选项标为Must？
- [ ] 是否忽略冲突和明确边界，或方案变化后沿用原评分？
- [ ] 是否尊重容量、角色和前置约束，资源不足时明确缺口，未知容量时不承诺日期？

> 共10条，按适用条件检查。缺证据应补验证动作，不自动补造分数、项目或排期。
